# 一键收集 Windows 崩溃日志

保持 App 的“VirtIO 显示设备”关闭，只开启“挂载驱动／日志盘”，再自行启用 JIT、启动 Windows。

在“此电脑”打开 `WINIOSDRV` 盘，双击 **一键收集日志.cmd**，权限提示选择“是”。出现“日志收集完成”后，回复“已收集”即可；不用复制文字或截图。

工具读取最近的蓝屏／异常关机事件、显示设备、驱动和崩溃转储设置；最多复制三份、每份不超过 8MiB 的已有小型转储，并读取已有 MEMORY.DMP 的前 64KiB。不会复制整个内存转储，不安装驱动、不改注册表、不重启 Windows。没有崩溃转储时也会保存事件记录及错误说明。

输出在同盘 `CRASHLOGS`。我会从 iPad 的工具盘镜像读取这些文件，在本机分析，不将崩溃记录上传到 GitHub。

## 准备新版驱动与后续蓝屏记录

同盘 **准备显示驱动与蓝屏记录.cmd** 是另一个会修改系统的工具。仅在 VirtIO 显示设备关闭时运行：核验包哈希，将微软签名的官方 302 版 ARM64 驱动加入 Windows 驱动库，保存原 CrashControl 设置，然后开启小型转储和蓝屏事件记录、关闭自动重启。保留旧驱动和分页文件设置，不改签名策略，不自动重启。

显示“准备完成”后回复“已准备驱动”。结果在 `PREPLOGS`，由我直接读取；后续一键收集也会附带准备结果。原设置保存在 `PREPLOGS/CrashControl-before.reg`。若分页文件未配置，即使开启小型转储仍可能无法生成 dump，应先根据记录判断，不能把“没有 dump”解释为没有发生蓝屏。
